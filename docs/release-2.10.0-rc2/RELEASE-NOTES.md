# COMMAND 2.10 consolidated test candidate

Desktop 2.10.0-rc.2 · bridge project 0.13.0 · matching included relay. Public release title after acceptance: COMMAND 2.10 — Mission Planning & Control. This candidate is not stable or publicly published.

## Core planning

Offline mission/ORBAT planning, asset selection, map annotations, briefings, project import/export, save/load, Undo/Redo, recovery, Settings, Sarge and English/French/German guidance remain available. Reusable deployment compositions preserve reviewed prefab identity and placement, insert with fresh identifiers and one Undo step. Missing index references stay visible; no automatic deployment is implied.

## Reviewed game integration — experimental

Explicit Quick connection and server-managed HTTPS relay modes, scoped tracking, approved spawning/removal, supported infantry controls and server-side scenario snapshots are retained. Three visible category controls report AI ORDERS, SPAWNING and REMOVAL ON/OFF; Disable All returns policy to manual and Companion reports the relay-confirmed policy. Snapshots and experimental helicopter flight retain separate manual approval.

Occupied deployment creates one vehicle with individual crew and optional real infantry-group cargo assignment, resolves native seats and verifies every required occupant. A group retains its actual identity/membership. Group seating is cargo-only with automatic slots; failure rolls back only the newly created batch while protecting players. Root counts and occupant counts are distinct. This direct seating does not fix the historical walking-to-vehicle timeout.

Ground reinforcement dispatch stages deployment and supported ground orders as separate reviewed actions; no unseen automatic waves. Refuel once requests one supported native stock interaction, respecting range/equipment/faction/scenario supplies, with actual fuel gain and supply consumption required for success. The isolated production request transferred about2.08litres, consumed the matching provider fuel and did not repeat the transfer on a duplicate request. Human multiplayer acceptance remains separate.

The optional vanilla UH-1H adapter demonstrates force-assisted Enfusion-physics flight on a bounded clear/flat route, sustained landing, four completed passenger exits and retained AI pilot. Occupied deployment and flight are two explicit approvals. Initial limits: one pilot, four cargo passengers, 20–100 m route near departure elevation, no obstacle avoidance. Any human entering any seat releases assistance. Airborne cancellation follows the approved route to a confirmed landing and retains passengers. Other helicopter profiles remain non-executable.

## Preserved boundaries

Historical boarding timeout remains unexplained. Broader combat, player takeover and multiplayer outcomes require live acceptance. Read-only 3D is a desktop terrain/proxy preview with authorized user data, not the rendered game world. Workbench exchange remains explicit; Apply, continuous two-way editing, exact game-model reconstruction, WebSockets, relay restart persistence and multi-admin roles are not delivered. Full roadmap remains in corresponding source.
