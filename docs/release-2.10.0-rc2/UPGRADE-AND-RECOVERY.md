# Upgrade and recovery

Back up your plan JSON and retain the previous app folder before changing builds. Extract this complete candidate beside it; do not overlay mixed runtime files. The app retains the existing user-data location for compatibility and does not auto-connect. Tests use isolated profiles, never your saved plan.

Desktop 2.10.0-rc.2 needs bridge project 0.13.0 and this relay for the new experimental capabilities. Stop the hosted scenario before replacing the mod, enable one addon copy, restart and pair afresh. Verify the actual downloaded Workshop version; local project files are not publication evidence. Never distribute a dashboard key or enabled private configuration.

Ordinary project format 4 remains supported. Plans with reviewed Workbench pose provenance can use format 5 and older readers may reject them; keep an original backup. Runtime tracking/flight state is not saved into ordinary mission JSON or Undo. An imported plan does not grant game ownership.

To recover, land or safely stop experimental operations first. Close the candidate and reopen the preserved app, then import the backup if required. Restore matching older bridge/relay together only after stopping the scenario. Switching app versions does not rewind the running game. Player entities remain protected.

Disconnect dashboard leaves a server-managed session running; End session revokes it. Airborne flight cancellation keeps assistance until its defined landing endpoint. A relay restart loses its in-memory session; a game/server process restart does not restore an airborne controller. Native snapshots cover supported COMMAND-managed entities, not every game system.
