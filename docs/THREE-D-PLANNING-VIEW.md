# Optional read-only 3D planning preview

Open **3D preview** on the map toolbar, or Settings → 3D planning preview. Import an authorized elevation JSON package, check its origin, scale and alignment, acknowledge permission, then open the terrain. The default world is the engine-verified Everon resource `{853E92315D1D9EFE}worlds/Eden/Eden.ent`, owned by addon `58D0FB3206B6F859`. This is a preconfigured identity reference; no game world layer or model is bundled.

Existing `command-terrain-observation` output can also be imported when its samples form a complete regular rectangle. The original native sampler still allows at most 300 selected points; for example a 17-by-17 local grid uses 289 points. Scattered points, holes or irregular spacing do not become an invented terrain surface. This does not supply a complete heightmap.

A dedicated `command-terrain-heightmap` package contains version 1, exact world identity, source name/reference/permission statement, grid columns/rows, X/Z metre spacing, origin, east/west column direction, north/south row direction, positive height scale, height offset, vertical reference and a complete row-major values array. The preview requires heights converted to **Enfusion world metres**. Missing/no-data samples are rejected. Maximum file size is 4 MiB, maximum 257 samples per edge. Imagery metadata, when present, must cover the section with its top edge north. UV alignment is generated; followon.11 can load the matching existing Everon base map or an authorized local PNG/JPEG with these extent fields.

Actual mesh vertex heights and triangle inspection share the same geometry. Repeated tactical proxies are instanced, with deliberately approximate dimensions and faction colors. Click a proxy to select the same planned unit in 2D. The inspection line shows its name and faction. No position edits, orders, game models or full `.ent` reconstruction are provided. Mission data and Undo history are not rewritten by inspection. Proxy orientation is neutral because current planned unit records do not store a per-unit 3D transform; no pitch/roll or parent transform is invented.

Controls: left drag orbits and right drag pans; the alternative binding swaps them. Wheel zooms toward the cursor. F focuses selection, R resets, Escape closes. Mouse scheme and zoom speed persist through the existing preference system and are available in Settings. Rendering loads on demand, draws only on changes and disposes instance objects, geometry, controls, renderer/context and canvas on close. Dataset memory is retained for reopening during the application session; it is not saved into the mission or sent to the game.

Verification currently includes original synthetic terrain, exact triangle/axis/heading checks, actual WebGL terrain raycasts and proxy picking, shared selection, translations, close/reopen and the maximum 257-by-257 grid with 60 proxies. The short maximum-grid sample used 3 draw calls and had 16.8 ms p95 browser frames with no stalls over 100 ms. This is not a guarantee for all PCs or datasets, nor proof of real-world imagery alignment. Three.js may retain an internal texture counter after disposal; the test separately verifies destroyed WebGL context, zero tracked geometry and removed canvas. [Official disposal guidance](https://threejs.org/manual/pages/how-to-dispose-of-objects.html).

## Independent desktop and bridge requirements

The read-only terrain-section preview is desktop-only and uses separately generated, authorized elevation files. It needs no Workshop update. Bridge 0.11.2 is required separately for the production AI-control, reconnect recovery and entity target-reporting changes shipped with this candidate. `Eden.ent` identifies a world; it is not a renderable mesh or a spawnable prefab. Full-world terrain, scene reconstruction, image import and exact game models remain separate work.

Lifecycle checks on this machine completed 20 consecutive open/close cycles offline, with one canvas while open, none after close, zero tracked geometry and destroyed graphics contexts. The coarse browser heap reading stayed at 23.1 MB; this is a short measured sample, not a leak-free lifetime guarantee. Missing elevation keeps the renderer unloaded with import guidance; incomplete elevation is rejected. Mission data remained unchanged.

Fresh native landmark validation used the exact engine-identified Game Master world `{BEF094A5F7F3211B}worlds/GameMaster/GM_Eden.ent`, whose reported subscene is Eden.ent. Morton, Montignac and Le Moule each supplied a 3-by-3 grid at 20-metre spacing: three 40-by-40-metre sections, 27 samples total. Actual desktop WebGL raycasts matched every sampled ground height with zero measured discrepancy and exact map/world landmark coordinate round trips. These files remain private diagnostic outputs; their raw elevation data is not bundled. Native location-entity origins are not assumed to be ground level. This does not attest other imported datasets or real image alignment.

## Followon.11 texture and presentation update

Matching textures now load on demand. Recognized Everon identities can use existing offline base-map imagery with the same +50-metre 2D conversion and correct north-up atlas orientation. An authorized local PNG/JPEG can instead use the heightmap’s explicit north-up imagery extent metadata. File bytes and encoded dimensions are bounded before decode. Texture/water preferences remain outside missions. Missing base imagery produces an explained shaded fallback. Water is at zero metres, and inspection distinguishes it from the seabed. Reset now fits the section’s projected corners to the actual viewport. No elevations are exaggerated or modified.

Eight real textured close/reopen cycles released geometry, the atlas texture, WebGL context and canvas; three landmark source-pixel comparisons matched the 2D planner. A texture is not reconstructed building/tree geometry. Game/editor windows stay separate; see [the three workflows](THREE-WORKFLOWS.md). Workbench editor-change import is explicitly planned until its importer, identity checks, added/moved/removed review and one-step Undo pass testing.
