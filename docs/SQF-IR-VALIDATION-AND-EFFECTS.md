# Source-bound IR verification and potential statement effects

## Delivered batch and boundaries

This developer-only stage adds strict source-bound replay validation for `command-sqf-control-context-ir` v1 and potential statement-effect review on that IR. It includes two fixed worker profiles, a read-only verifier command, an effect-report command, adversarial tests, performance evidence and EN/FR/DE developer guidance. It does not add an app import route, execute SQF, change missions, generate Enforce code or verify native adapters.

## Strict verification requires the source

`planner/sqf-control-context-validation.js` exposes `validate(report, files)` and `verify(report, files)`. It snapshots both inputs before asynchronous source hashing yields, rebuilds the IR from the supplied source through the existing producer and compares every field. Validation rejects altered source identities, hashes, ownership, node/edge/slot IDs, bindings, inferred exit targets, type/execution claims, review gates, findings and summaries. Recomputing an attacker-controlled summary or context hash does not bypass the source replay comparison.

Object field order is immaterial; array order and all data values remain significant. On success, `validate` returns the freshly rebuilt canonical report, not the imported objects. Returning that trusted result avoids a redundant full clone of the producer output. `verify` returns a non-executable source-match receipt with `sourceReplayMatched:true` and `nativeVerified:false`.

This checks consistency with the **current bounded producer and matching source**, not source-free report validation, authorship, signatures, complete SQF semantics or native readiness. A report regenerated by a changed producer may need to be rebuilt before verification. Unsupported source/review blockers remain unsupported after a successful match. Matching malicious source text is still just matching source text; it is never executed or made authoritative for a game command.

The input snapshot walks data iteratively using property descriptors. Accessors, functions, proxies, custom prototypes, symbol/non-enumerable fields, non-finite numbers, sparse/extended arrays, cycles and excessive nesting/work/text are rejected before serialization. Plain null-prototype records, dense frozen arrays and acyclic shared records are accepted; repeated records are independently copied and charged each time. No imported `toJSON`, `toString` or getter is invoked. The original producer's harmless shared records therefore remain acceptable without allowing cycles or repeated data to bypass size accounting.

Snapshot limits: depth 64, 1,000,000 visited values, 50,000 items per dense array and the IR's 16 MiB text/compact-byte budget. The rebuilt source still has the existing structural/binding source and graph limits. The exact comparison is iterative; no imported recursive graph traversal or target code is run. This new source-bound validator is not an assertion that every other legacy report format now has an equivalent validator.

## Read-only verification command

```powershell
node tools/sqf-review/verify-control-flow.cjs --source-set "A:/Reviews/sqf-files.json" --report "A:/Reviews/control-context.json"
```

Source-set JSON is exactly `{files}`. Both files must be bounded regular UTF-8 files; symbolic links and non-regular files are rejected. Reads are chunk-bounded even if a file grows after its initial size check. After the worker returns, both raw byte hashes are rechecked. Verification writes no files and prints a receipt with source/report byte hashes; those hashes are evidence of the checked bytes, not signatures or native behavior proof.

Raw source-set JSON is bounded to 16 MiB; raw report files to 64 MiB so pretty-printed reports can be read. After JSON parsing, the verifier compacts the source/report envelope for the fixed `flowverify` worker, whose separate input cap is 20 MiB. The IR itself still has a 16 MiB compact report limit and matching source has a 2 MiB structural budget. Other worker profiles retain their original 16 MiB input limit. A large report may therefore be rejected by an earlier raw/envelope/data budget before replay; it is never truncated.

Existing worker memory limits, timeouts, cancellation and awaited cleanup apply. The CLI's raw-byte check detects changed files; the core validates captured data values. Duplicate raw JSON object keys follow the JSON parser's last-key semantics, so this is normalized-data/source consistency, not canonical raw-JSON authentication. No dependency fetching or implicit referenced-file reads occur.

## Potential statement-effect review

`planner/sqf-statement-effects.js` exposes `build(files)` and `reviewImported(ir, files)`. The first builds its own source IR once; the second performs source-bound validation before reviewing it. Neither accepts unverified imported effect facts. Both produce the same deterministic source-derived review for the same input.

Node rows record potential assignment writes, symbol reads, array/code construction, branch/loop/exit uncertainty and unsupported source coverage. Command candidates reuse the project's immutable bounded source-command rules and preserve source links, obligations and unresolved operand/native flags. These are potential effects even when operand types or the actual call remain invalid/unresolved; the pass is not a command type checker or full statement-effect analyser.

Additional candidates preserve distinctions already needed by the source semantics:

- Events: subscription and deferred callback candidates with owned cleanup/lifetime obligations.
- Actions: deferred action-code and per-frame condition-string candidates, with source scheduling still not mapped to a target adapter.
- `isNil`: syntactic code versus string forms retain different possible invocation/binding-read effects.
- Logical operators: code right operands retain conditional invocation candidates; Boolean right literals retain eager-operand review labels. No constant folding or target short-circuit assumption is made.
- `getVariable`: array argument/default expression work carries an eager-work review obligation.
- `select`: a code operand retains a possible per-element invocation, without proving the collection/overload types.

Invocation rows link to the matching detached source context where one is identified. Missing/string/dynamic callback context remains unresolved. A callback candidate is not an executed callback or verified scheduler policy. Its body effects stay in the detached context; they are not merged into the owning file/statement as if invoked already. Context summaries union only potential effects from nodes in that same context. Branch/loop child regions in that context remain potential, not definitely reached work. Unknown syntax forces unknown coverage, and zero detected effects never proves purity.

This pass adds context-level review evidence, not flow-sensitive initialization, complete mutation analysis, sound whole-program effects, verified return/exit semantics, target-native scheduling or an executable control-flow graph.

## Effect command and contract

```powershell
node tools/sqf-review/statement-effects.cjs --source-set "A:/Reviews/sqf-files.json" --output "A:/Reviews/new-statement-effects.json"
```

The fixed `effects` worker accepts exactly `{files}` and reuses existing source checks, bounded worker, cancellation/deadlines, original-byte recheck and exclusive fresh-file output. Source is never evaluated. Reports contain the unchanged embedded control/context IR, source/rule-set fingerprints, node/context summaries, command candidates, invocation candidates and mandatory review gates. Source-derived names/literals must only be shared with appropriate rights.

The output is `command-sqf-statement-effect-review` v1. Top-level `executable`, `evaluationPerformed`, `effectsResolved`, `fullStatementEffectsAnalyzed`, `controlFlowLowered`, `targetTypesResolved` remain false; `summary.executionReady` stays zero. Invocation, command, node and context rows retain their corresponding unresolved flags. The effect rule-set hash identifies the project rule data used, not engine verification.

Additional limits: 20,000 command candidates, 10,000 invocation candidates, 100,000 aggregate effect/obligation label references and a 16 MiB combined compact report, plus inherited IR/source bounds. Overflow rejects rather than truncates. Existing app import contracts and seven-analysis bundles remain unchanged. The new effect report has no separate imported-effect authority; `reviewImported` only accepts source-replayed control/context IR and rebuilds the effect evidence itself.

## Tests and sampled source evidence

38 new focused cases and 38 affected regression cases passed. Adversarial coverage includes graph/type/readiness promotion, changed/missing source, forged hashes/IDs/ownership/exit destinations, removed gates/findings, altered binding evidence, malformed expression facts, object order versus array order, accessor/proxy/toJSON/cycle/sparse/prototype/non-finite payloads, budgets and asynchronous caller mutation. Effect tests cover detached lifetimes, conditional/loop potential work, documented candidate obligations, callback links, unknown coverage and source-replayed imported IR. Workers/CLI cover strict shapes, cleanup, separate byte caps, read-only verification, UTF-8/regular-file rejection and fresh-output-only writes. Later optimization/reader edits were checked with only their affected tests locally.

Five private cached source sets (30 selected SQF files) match their previous IR reports exactly. Sources and saved IR bytes remain unchanged. New evidence contains 103 command candidates, 13 invocation candidates and 354 potential-write nodes; 132 of 141 contexts retain unknown coverage. These figures describe selected review evidence, not native conversion, resolved calls or whole-mod completeness. No source was downloaded or executed for this pass.

## Measured cost

The same 16-file/160-function fixture used by the prior IR evidence produces a 5,319,434-byte compact IR. Two warmups and six measured sets gave median 124.83 ms IR-only, 150.18 ms with potential effects, 371.27 ms for source-replay validation including an equality assertion, 326.66 ms through a fresh effect worker and 503.15 ms through a fresh verification worker. Fresh-worker timings include startup/return/termination. Direct/worker output matched and source bytes/old IR remained unchanged.

These samples measure added source-review/integrity work, not an app speedup, renderer/FPS guarantee or native stability result. The fixture has 3,376 IR nodes and 1,120 write candidates but no supported command candidates; real-corpus command/callback coverage and focused callback tests are recorded separately. Evidence: `docs/test-evidence/sqf-statement-effects-validation.json`.
