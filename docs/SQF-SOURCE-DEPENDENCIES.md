# Supplied-source include dependency review

## Delivered developer capability

`planner/sqf-source-dependencies.js` inventories preprocessor directives and resolves literal includes against a bounded, explicitly supplied set of source texts and virtual-prefix mounts. It performs no filesystem access, preprocessing, macro expansion, code execution or native deployment. This is a developer-only core plus Node worker/CLI; it is not installed desktop functionality and does not yet add cross-file symbol binding. Existing app Sarge/Settings topics and bridge behaviour are unchanged. EN/FR/DE developer instructions are appended to tools/sqf-review/README.md.

Bohemia documents quoted and angle-delimited includes as equivalent, relative to the current source file unless the path starts at the virtual root. Its engine also has file-patching paths that this tool intentionally does not access: [preprocessor commands](https://community.bistudio.com/wiki/Config_Parser), [addon prefix](https://community.bistudio.com/wiki/PBOPREFIX?useskin=darkvector). Here a leading slash/backslash is an explicit virtual-prefix request; drive paths, UNC/URL paths, control characters and traversal outside the selected source boundary are rejected as unsafe findings. Relative parents within the source set are allowed. Virtual paths cannot traverse above the matched mount root. No missing dependency is automatically downloaded.

## Contract and boundaries

Input is a dense plain array of `{name,text}` source records plus dense plain `{prefix,root}` mount records. Source identities are relative and support only loose SQF/SQM/EXT/HPP/INC/CPP text. Configuration files are inspected solely for directives, not parsed as SQF or as complete CfgPatches/CfgFunctions. PBO/WRP/binary input is rejected. Accessor fields, sparse/extended arrays, duplicate exact source names and unsafe paths are rejected before scanning. Case-colliding source identities remain explicit findings.

Reports use `command-source-dependency-review` v1, UTF-16 source offsets and decoded UTF-8 text SHA-256 identities. A domain-separated source-set hash includes ordered identities and mounts. This is content identity, not authorship or semantic proof. There is no import/app-execution authority for this new report type. Full strict imported-report validation remains necessary before adding an app import route.

Include results distinguish exact matches, case review, ambiguous case, ambiguous mounts, missing files, unmapped virtual prefixes, unsafe paths and unsupported include expressions. Mount matching uses segment boundaries and the longest explicitly provided prefix; equally specific competing mounts remain ambiguous. A prefix spelling mismatch also requires case review. Case-review targets are not promoted to exact graph edges.

Lexical masking prevents ordinary comments, quoted strings and continued macro bodies from fabricating directives. LF, CRLF and CR line endings preserve source spans. Literal include operands are recognized; macro-computed or continued include operands remain unsupported. Other directives are inventoried and require review. This is not a replacement for Arma's preprocessor: malformed lexical regions and unmatched/open conditional nesting are reported, cross-file conditional state and macro expansion are not modeled. Every include has activation `not-evaluated`, including branches under `#if 0`. All files in the supplied set are scanned, not just a proven reachable entry graph. Potential cycle edges are graph evidence only; include guards and conditions can change actual activation.

Bounds: 256 files; 256 KiB per file; 8 MiB aggregate source; 64 mounts; 8,192 directives; 4,096 includes; 16,384 aggregate candidate references; conditional depth 128; compact report 8 MiB. Exceeding a bound rejects the review rather than publishing partial success.

## Worker and CLI

`tools/sqf-review/dependency-runner.cjs` runs JSON parsing and analysis in a Node worker with a 256 MiB old-generation ceiling, 4 MiB stack, 15-second default deadline (maximum 30 seconds) and explicit cancellation. The result promise awaits worker termination after success, rejection, cancellation or timeout. Workers provide event-loop isolation, not a security sandbox; supplied text is never evaluated.

`dependencies.cjs` reads one user-selected, regular UTF-8 JSON file, capped at 16 MiB, with exactly `{files,mounts}`. It checks source JSON byte identity after inspection and exclusively creates a new report file; it cannot overwrite a source or previous report. Invalid encoding, non-regular input and rejected source sets produce no report. Reports are not part of the existing version-4 seven-analysis bundle; old review formats and tools remain unchanged.

## CI and toolchain choices

`.github/workflows/sqf-review.yml` adds relevant-path push/PR/manual checks on Linux Node 24 and Windows Node 22. Both official actions are pinned to verified commit SHAs; checkout credentials are not persisted. The workflow uses read-only contents permission, cancellation of superseded runs, a ten-minute timeout and no dependency installation, game launch, third-party corpus downloads, secrets, release publishing or write tokens. `test:sqf-core` includes the bounded core/report/CLI tests. The exact configured test selection passed 158 local checks on Node v24.19.0, launched through the bundled Node runtime because npm is not bundled locally. Both hosted matrix jobs then passed for source b00115f742f74db9be7698567f6cf2b9ccad356e: [GitHub Actions run 38748374896](https://github.com/GrimActual/COMMAND-ORBAT-Mission-Planner/actions/runs/38748374896). Hosted results and local evidence remain separately recorded. Node 18 remains the documented developer minimum, but is not this CI matrix's coverage claim.

Tree-sitter/ANTLR grammar evaluation is pending: test supported/unsupported syntax, preprocessing boundaries, source maps, error recovery, deterministic output, depth/memory limits and licence/provenance against pinned fixtures before selecting a grammar. Neither library is integrated here. AST visitor-style passes already separate structure, expressions, bindings and effects; jscodeshift is not used as an SQF parser. GNU CPP is also not integrated: compare actual Arma macro/include/conditional behaviour on isolated fixtures before choosing compatibility options; never pass author filenames/options directly to a shell. Current desktop SQF inspectors use browser workers, existing metadata/simulation use Node threads, and this new developer dependency analysis now uses Node threads too. The other developer-only cores are not all worker-backed.

The suggested SLSA generator's [maintainer documentation](https://github.com/slsa-framework/slsa-github-generator#readme), checked 15 October 2026, states it is no longer actively maintained and directs users toward GitHub artifact attestations. Plan artifact attestations against actual CI-built release artifacts with verification instructions; do not attach provenance suggesting old locally built releases were built in CI. No SLSA level, attestation or release workflow is claimed by this test-only checkpoint. Webpack and Anaconda are not introduced because these tools use plain Node with no Python package build requirement.

Next: bounded source-mapped preprocessing and function/config registration inventory, followed by cross-file symbol candidates and typed context/control-flow IR. The author-operated in-app conversion workflow, explicit mapping review, native adapters and isolated compile/behavior gates remain the product destination.
