# COMMAND Huey-Einsatz prüfen

Nur die passende konsolidierte Test-App, das Bridgeprojekt 0.13.0 und den mitgelieferten Relay verwenden. Experimentell; Mehrspielerabnahme steht aus. Eigenen Plan vorher sichern.

`01-MISSION-PLAN.json` als Projekt importieren, bei Bedarf `02-ASSET-CATALOG.json` unter Assets laden, dann `03-RESOURCE-INDEX.json` über Import Workbench metadata → Load resource index JSON → Use reviewed resource index verwenden. Im Spiel Start X 4771 Z 11637 und freie, ebene Landezone X 4771 Z 11737 prüfen.

HUEY, PILOT und TEAM auswählen. Unter Game controls → Deploy den Einsatz prüfen. In Occupied vehicle deployment diese Prüfung übernehmen: Fahrzeug HUEY, PILOT mit automatischem pilot-Sitz, tatsächliche Gruppe TEAM mit automatischen cargo-Sitzen, 30 Sekunden. Prüfen, senden und in Reforger genehmigen. Einen Piloten und vier sitzende Gruppenmitglieder tatsächlich bestätigen. Drei Wurzeleinträge ergeben fünf Insassen. Kein laufender Einsteigebefehl nötig.

Game controls → Orders → Helicopter insertion — experimental öffnen. Aktualisieren, TEAM/HUEY wählen, Landezone X 4771 Z 11737 markieren und geprüfte freie Route bestätigen. Prüfen, senden, manuell genehmigen. Ablehnen muss das Flugzeug unverändert lassen. Erfolg erfordert Start, Flug, anhaltend bestätigte Landung, vier abgeschlossene Ausstiege und verbleibenden Piloten.

Abbruch in der Luft behält die Assistenz bis zur genehmigten Landezone und die Passagiere an Bord. Begonnene Ausstiege sind nicht rückrufbar. Jeder Mensch auf einem beliebigen Sitz beendet die Assistenz: Beobachter bleiben draußen. Kompetente menschliche Übernahme und Tests mit zwei Clients stehen aus. Andere Luftfahrzeuge bleiben deaktiviert; der historische Timeout beim laufenden Einsteigen ist ungeklärt.
