# Essai d’insertion COMMAND — Huey

Utilisez uniquement l’application candidate consolidée, le projet de pont 0.13.0 et le relais correspondants. Fonction expérimentale ; acceptation multijoueur non établie. Sauvegardez votre plan.

Importez `01-MISSION-PLAN.json` comme projet,`02-ASSET-CATALOG.json` dans Assets si nécessaire, puis `03-RESOURCE-INDEX.json` via Import Workbench metadata → Load resource index JSON → Use reviewed resource index. Inspectez dans le jeu le départ X 4771 Z 11637 et la zone plate X 4771 Z 11737.

Sélectionnez HUEY, PILOT et TEAM. Vérifiez leur déploiement dans Game controls → Deploy. Dans Occupied vehicle deployment, utilisez ce déploiement : véhicule HUEY, PILOT en siège pilot automatique, groupe TEAM en sièges cargo automatiques, délai 30 secondes. Vérifiez, envoyez puis approuvez dans Reforger. Confirmez un pilote et les quatre membres du groupe assis. Trois entrées racines produisent cinq occupants. Aucun ordre de marche vers le véhicule n’est requis.

Ouvrez Game controls → Orders → Helicopter insertion — experimental. Actualisez, choisissez TEAM/HUEY, marquez la zone X 4771 Z 11737 et confirmez le trajet inspecté. Vérifiez puis envoyez et approuvez manuellement. Un refus doit laisser l’appareil immobile. La réussite exige décollage, vol, atterrissage stable, quatre sorties terminées et pilote conservé à bord.

Une annulation en vol conserve l’assistance jusqu’à cette zone et garde les passagers à bord. Les sorties déjà engagées ne peuvent pas être rappelées. Tout humain entrant dans un siège arrête l’assistance : les observateurs restent dehors. La prise de contrôle humaine compétente et les essais à deux clients restent à effectuer. Aucun autre hélicoptère n’est activé ; le délai historique d’embarquement à pied reste inexpliqué.
