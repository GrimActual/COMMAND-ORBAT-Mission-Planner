# Reproduce the isolated pure Boolean fixture

This prepares original diagnostic sources only. It never launches an executable or changes the Workshop bridge. From the repository root, use your Node installation:

```text
node tools/boolean-mapping/prepare.cjs "D:/Tests/NewBooleanProof"
```

The absolute destination must not exist. The helper writes addon.gproj, Scripts/Game and expected-cases.json. Existing folders are refused. The values class is generated by the same mapping and has the fixture SHA recorded in planner/native-evidence/pure-boolean-v1.json.

With an installed, matching diagnostic server/base-game addon directory, explicitly run ArmaReforgerServerDiag.exe with `-gproj <new-project>/addon.gproj -addonsDir <base-addons> -profile <private-test-profile> -server "{55A3176BBDD01AAE}worlds/Eden/EmptyEden.ent" -port 29993 -maxFPS 10 -noSound -noSplash -noThrow`. The world reference was observed in 1.8.0.13; resolve/check your installed resources rather than assuming other versions match. Use an isolated profile and stop the diagnostic server after the result. Do not substitute a game client or public production server.

Expected script log: `[COMMAND BOOL] CASES=46 FAILURES=0 VERSION=1.8.0.13`. A missing line, nonzero failures, script error, timeout or startup crash is not a pass. The recorded run used a 75-second deadline and 1,200 MiB sampled memory bound; the preparation helper itself does not monitor/launch processes or mint proof receipts. Review native logs and code before changing verification evidence. Sources need no pairing credentials or relay and spawn no entities. The initial Workbench startup crash is retained as a failure, not repeated in this workflow.

See docs/BOOLEAN-EXPRESSION-MAPPING.md for semantic scope, source references, proof identity, desktop export and remaining integration requirements. No SQF source is executed; target tests compare documented literal-only Boolean results. No full program, callback, scheduler or multiplayer behavior is claimed.
